CORE CAPABILITIES

Built on Genuine Linux Kernel & User-Space Evidence

Every diagnostic metric originates directly from GCC, the LDST C debugging core, strace, Linux /proc, and GDB.

Powered by strace

SYSTEM CALL TRACING

Intercepts and records actual kernel system calls made by target C programs, separating dynamic-loader initialization noise from relevant application failures.

Live Linux /proc information

PROCESS MONITORING

Reads live process telemetry from /proc/<pid>/status, /proc/<pid>/stat, and /proc/<pid>/fd to track PID, PPID, state, VmSize, VmRSS, threads, and open FDs.

errno, signals and termination analysis

ERROR ANALYSIS

Pinpoints failing system calls returning -1, decodes POSIX errno codes (such as ENOENT, EBADF, EACCES), and inspects waitpid() exit and signal states.

GDB-assisted crash investigation

CRASH DEBUGGING

Automatically launches batch GDB investigation upon fatal signals like SIGSEGV or SIGABRT to capture stack frames and identify the exact crashing C source line.

SYSTEM ARCHITECTURE

One C Debugging Core. Dual Interfaces.

LDST is an Operating Systems and Systems Programming project. The browser GUI sits directly on top of the native C debugging binaries (./debugger and ./autodebug), while preserving the interactive terminal console launcher (./ldst).

  • Process Management: Child creation with fork(), program loading via execvp(), and non-blocking state collection with waitpid().
  • System Call & errno Inspection: Real-time strace capture and automated classification of kernel error codes.
  • Procfs Telemetry: Live reading of /proc/<pid>/status, /proc/<pid>/stat, and /proc/<pid>/fd.
  • Crash Forensics: Automated batch GDB invocation on SIGSEGV/SIGABRT to extract stack frames and source lines.
